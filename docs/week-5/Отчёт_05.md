# Домашнее задание V: SLI, SLO, SLA

## Метрики и индикаторы

Используется RBSLO: доля хороших запросов среди завершённых попыток. Семь SLI построены на двух семействах метрик:

- **`fileserver_operations_total`**: Counter завершённых операций. Для каждой операции: `N_<operation>`- прирост всех попыток, `G_<operation>` - часть прироста с `outcome="success"`.
- **`fileserver_operation_duration_seconds`**: Histogram длительности в секундах. `T_<operation>` - прирост `_count`, `F_<operation>` - прирост `_bucket{outcome="success",le="1"}`. Таким образом

| SLI | Формула | SLO | SLA |
|---|---|---|---|
| Успешность `login` | `100 × G_login / N_login` | $\geq 99\%$ | $\geq 95\%$ |
| Успешность `register` | `100 × G_register / N_register` |  $\geq 99\%$ | $\geq 95\%$ |
| Успешность `logout` | `100 × G_logout / N_logout` | $\geq 99,9\%$ | $\geq 99\%$ |
| Успешность `upload` | `100 × G_upload / N_upload` |  $\geq 99,5\%$ | $\geq 99\%$ |
| Успешность `download` | `100 × G_download / N_download` | $\geq 99,9\%$ | $\geq 99\%$ |
| Успешный вход за $\leq 1$ с | `100 × F_login / T_login` | $\geq 99\%$ | $\geq 95\%$ |
| Успешная регистрация за $\leq 1$ с | `100 × F_register / T_register` | $\geq 99\%$ | $\geq 95\%$ |

## Изменения приложения

- Лимит запросов к API поднят до 60 миллионов операций в минуту _(ранее: 300 запросов в минуту с одного IP)_. **Причина поднятия лимита:** при ограничении 300 запросов в минуту при стресс-тесте сервер начинает слать `HTTP 429 Too Many Requests` в скором времени после запуска.

- Добавлен новый dashboard в Grafana для отслеживания SLI, SLO, SLA.
