# Домашнее задание I: The Twelve Factor App

## Доменная область

Приложение представляет собой файловый сервер. Пользователь может зарегистрироваться, войти в систему, загрузить/скачать/переименовать/удалить файл, получить список загруженных файлов.

## Стек реализации

**Back-end:** Go _(`net/http`, `pgx/v5`, `goose`)_  
**Front-end:** HTML, CSS, JavaScript  
**Хранилище:**
- PostgreSQL _(пользовательские данные, метаданные файлов, данные сессии)_
- SeaweedFS _(данные файлов)_

**Контейнеризация:** Docker  
**Оркестрация:** Docker Compose  

## Основные сущности

| Сущность | Назначение | Операции |
|---|---|---|
| `User` | Пользователь приложения: идентификатор, имя, хэш пароля | Регистрация, вход, получение данных пользователя |
| `File` | Файл пользователя: владелец, имя, размер, MIME-тип, ключ объекта, состояние (`uploading`/`deleting`/`ready`) | CRUD: загрузить (C); скачать/просмотреть (R); переименовать (U); удалить (D) |
| `Session` | Токен сессии: SHA-256 хэш, пользователь, дата создания и срок действия | Создать, проверить, аннулировать, expire/очистить |
| `Request limit` | Счётчик/ограничитель запросов: ключ, счётчик, expiry окно | Прибавить, сбросить, expire, очистка |

## I. Codebase

Back-end, front-end, миграции и конфигурация сборки хранятся в одном [репозитории](https://github.com/semyonnadutkin/SRE-F26).

## II. Dependencies

Go-зависимости объявлены в `go.mod` и `go.sum`, Docker образы фиксируются в конфигурации.

## III. Config

Параметры окружения, подключения к PostgreSQL и S3, длительность сессии передаются через переменные окружения.

## IV. Backing services

PostgreSQL и S3-хранилище подключаются как внешние сервисы через конфигурацию.

## V. Build, release, run

Dockerfile отвечает за сборку образа _(build)_, конфигурация передаётся при запуске, а миграции выполняются отдельной командой.

## VI. Processes

Go-бэкенд не хранит состояние локально - состояние хранится в PostgreSQL и S3. Пользовательские сессии не зависят от памяти конкретного процесса.

## VII. Port binding

Приложение поднимает HTTP-сервер самостоятельно и принимает соединения на заданном порту.

## VIII. Concurrency

Несколько экземпляров приложения могут использовать общие PostgreSQL и S3.

## IX. Disposability

Приложение корректно обрабатывает `SIGINT` и `SIGTERM` сигналы, выполняя корректное завершение HTTP-сервера.

## X. Dev/prod parity

В разных окружениях для запуска используется одинаковое приложение, миграции и сетевые протоколы PostgreSQL/S3.

## XI. Logs

Приложение пишет логи в JSON формате в поток стандартного вывода.

## XII. Admin processes

Миграции, инициализация S3 bucket и очистка запускаются отдельными командами того же бинарника с той же конфигурацией окружения.
