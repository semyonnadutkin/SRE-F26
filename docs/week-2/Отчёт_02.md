# Домашнее задание II: Kubernetes манифесты

## Использованные абстракции Kubernetes

### Namespace
Namespace `fileserver` объединяет ресурсы приложения.

### Pod
Компоненты запускаются в отдельных Pod: `fileserver-cleanup`, `fileserver-deployment`, `postgres`, `s3`.

Pod'ом файлового сервера управляет Deployment `fileserver-deployment`, pod'ами PostgreSQL и S3 - соответствующими StatefulSet.

### StatefulSet

PostgreSQL и S3 (SeaweedFS) pod'ы запускаются в отдельных StatefulSet и получают стабильные имена.

Для каждой компоненты создаются PVC размером 5гб с режимом доступа ReadWriteOnce. PostgreSQL монтирует `/var/lib/postgresql`, SeaweedFS - `/data`.

SeaweedFS запускает `master`, `volume server`, `filer` и S3-интерфейс в одном контейнере. Для метаданных `filer` настроено хранилище LevelDB в `/data/filerldb2`, которое также находится на постоянном томе.

### Service
- Сервисы типа ClusterIP предоставляют постоянные внутренние адреса.
`fileserver	80` передаёт HTTP-запросы на порт 8080 готовых Pod файлового сервера. `postgres 5432` - подключение файлового сервера к PostgreSQL,
`s3 8333` - доступ файлового сервера к S3 API SeaweedFS

- Headless-сервисы `postgres-headless` и `s3-headless` имеют `clusterIP: None` и используются соответствующими StatefulSet для стабильной DNS-адресации Pod. В частности, SeaweedFS использует адрес `s3-0.s3-headless.fileserver.svc.cluster.local` для объявления своего адреса внутренним компонентам. Параметр `publishNotReadyAddresses: true` позволяет публиковать адреса Pod ещё до прохождения проверки готовности.

### Ingress
Ingress с классом `nginx` направляет запросы с префиксом `/` в сервис `fileserver:80`. Аннотации задают максимальный размер тела запроса 64мб, тайм-ауты чтения и отправки 660 секунд и отключают буферизацию тела входящего запроса. Ingress-контроллер включается императивно при помощи команды `minikube addons enable ingress` перед применением манифестов _(см. [README.md](README.md))_.

### ConfigMap и Secret
- ConfigMap хранит настройки: порт приложения, адрес S3, регион, имя bucket, срок действия сессии, ограничение размера файла, имя базы данных и конфигурацию `filer`.

- Файловый сервер получает настройки через переменные окружения, а конфигурация SeaweedFS монтируется в `/etc/seaweedfs`.

- Secret используется для строки подключения к PostgreSQL, пароля базы данных и ключей доступа к S3. Файловый сервер и служебные задания получают нужные значения через `envFrom` или `secretKeyRef`.

### Job и CronJob
Для разовых операций используются отдельные Job с тем же образом приложения:
- `fileserver-migrate`: применение миграций базы данных
- `fileserver-bucket-init`: инициализация S3-bucket
- `fileserver-audit`: запуск служебного аудита

У разовых заданий заданы ограничения повторных попыток и времени выполнения. `ttlSecondsAfterFinished: 600` обеспечивает удаление завершённых Job и принадлежащих им Pod через 10 минут.

- CronJob `fileserver-cleanup-cron` запускает команду `cleanup` каждые 15 минут. `concurrencyPolicy: Forbid` запрещает одновременный запуск нескольких заданий этого CronJob. Сохраняется история одного успешного и трёх неуспешных заданий.

## Взаимодействие сервисов

1. Клиент отправляет HTTP-запрос на [localhost](http://127.0.0.1).
2. Ingress выбирает правило для пути `/` и направляет запрос сервису `fileserver` на порт 80, который является отображением порта 8080 контейнера.
3. Файловый сервер обрабатывает запрос и обращается к PostgreSQL по адресу `postgres:5432` и к S3 по адресу `http://s3:8333`.
4. Ответ файлового сервера возвращается клиенту через Nginx.
