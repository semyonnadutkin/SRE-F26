# Домашнее задание IV: VictoriaMetrics

## Стек

VictoriaMetrics устанавливается Helm-чартом `vm/victoria-metrics-single`. Метрики собираются каждые 15 секунд, цели обнаруживаются через service discovery с `role: pod`. Аннотации `prometheus.io/scrape`, `prometheus.io/port`, `prometheus.io/path` задают разрешение сбора, порт и путь.

### Runtime и бизнес метрики
Для сбора runtime и бизнес метрик используется пакет `github.com/prometheus/client_golang/prometheus`. Клиент Prometheus автоматически собирает runtime метрики и отдаёт их и зарегистрированные бизнес метрики по пути `/metrics`.

Бизнес метрики регистрируются как глобальные переменные типов `prometheus.Counter` и `*prometheus.HistogramVec` _(Counter и Histogram типы метрик соответственно)_. Код обновляет значения переменных через предоставленные методы `Inc()` и `Observe()`.

### Использованные экспортеры

#### PostgreSQL
Используется рекомендованный `postgres-exporter` как sidecar-контейнер в pod'ах `postgres`. Работает на порту 9187 и отдаёт метрики по маршруту `/metrics`.

#### SeaweedFS (S3)
Используется встроенный Prometheus экспортер. Работает на порту 9324 и отдаёт метрики по маршруту `/metrics`.

## Реализованные бизнес метрики

| Метрика | Тип | Что измеряет |
|---|---|---|
| `fileserver_logins_total` | Counter | Число успешных входов |
| `fileserver_registrations_total` | Counter | Число успешных регистраций |
| `fileserver_uploads_total` | Counter | Число загрузок, завершившихся сохранением файла и фиксацией метаданных |
| `fileserver_downloads_total` | Counter | Число скачиваний, для которых сервер передал ожидаемый объём данных без ошибки |
| `fileserver_operation_duration_seconds` | Histogram | Длительность обработчиков в секундах; метка `operation`: `login`, `signup`, `upload`, `download` |
